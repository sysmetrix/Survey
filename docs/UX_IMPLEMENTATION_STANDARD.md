# 화면 구현 기준

이 기준은 새 화면과 기존 화면 수정에 모두 적용한다. 기능을 추가할 때 기존 조작 가능성을 줄이지 않는다.

## 행동 영역

- 기본 행동은 제목과 같은 패널 안에 둔다. 탭, 고정 헤더, 떠 있는 요소 뒤에 겹치게 두지 않는다.
- 버튼은 잘리거나 말줄임표로 숨기지 않는다. 공간이 부족하면 다음 줄로 이동하고, 좁은 화면에서는 가로 전체를 사용한다.
- 하나의 패널에는 주 행동 하나를 우선 배치한다. 보조 행동은 같은 줄에서 줄바꿈할 수 있어야 한다.

## 정보 구조

- 관계를 이해하는 화면은 지도·흐름으로, 여러 값을 바꾸는 화면은 세로형 카드 목록으로 제공한다.
- 처음 여는 화면은 가장 자주 필요한 작업을 기본으로 선택한다. 분석 전 설정 화면은 확인 필요 항목과 핵심 입력부터 보여 준다.
- 보조 모드는 그 목적이 제목만으로 이해되어야 한다. 모호한 표현 대신 `문항 연결 구조`처럼 사용자가 확인할 대상을 이름으로 쓴다.
- 넓은 표는 읽기 전용 비교에만 쓴다. 편집에 필요한 필드가 많으면 문항 또는 지표별 카드로 묶는다.
- 지도를 추가해도 기존의 이름, 역할, 범위, 토글, 세부 설정 기능은 접근 가능한 화면에 모두 남긴다.
- 분석 결과에 영향을 주는 설정은 숨기지 않는다. 접을 수 있는 영역은 보조 설명과 드문 고급 기능에만 사용한다.

## 반응형 규칙

- 1280px, 1024px, 768px, 390px 폭에서 제목·탭·주 행동·입력칸이 서로 겹치거나 잘리지 않아야 한다.
- 가로 공간이 부족하면 카드 열 수를 줄이고 행동 버튼을 다음 줄로 보낸다. `overflow: hidden`으로 문제를 감추지 않는다.
- 탭은 콘텐츠 위를 덮지 않는다. 고정 탭이 필요한 경우에도 해당 콘텐츠의 안전 여백을 확보한다.

## 완료 조건

- 변경한 화면의 핵심 행동 버튼이 모든 기준 폭에서 완전한 이름과 클릭 영역으로 보인다.
- 기존 조작 항목의 삭제 여부와 빈 상태·필터 0건 상태를 테스트한다.
- 렌더링 테스트, 서비스워커 갱신, 버전 표기를 함께 확인한다.
